# Задачи носильщиков и панель работника

## Автоматическое подключение

ResourcesMove добавляет CarrierTask носильщику автоматически. Старый путь операций носильщика отключён, чтобы одни и те же ресурсы не переносились двумя независимыми системами. Перед первой задачей работник по-прежнему посещает место найма.

Панель создаётся пользователем в Canvas. На отдельный объект панели добавить SelectedWorkerPanel: CanvasGroup добавится вместе с компонентом. Создать дочерние TextMeshPro UI и назначить поля Worker Name Text, Task Text, Cargo Text, Capacity Text и Reservation Text. Ненужные поля можно не назначать. Размер, расположение, фон и оформление задаются в редакторе. Скрипт не создаёт визуальные объекты автоматически и не использует OnGUI.

Объект панели должен оставаться активным: скрипт скрывает его через CanvasGroup, чтобы продолжать следить за выделением. Не размещать компонент на общем Canvas, иначе скрываться будет весь Canvas. При одиночном выделении рабочего показываются текущая задача, груз, вместимость и резерв места; при групповом выделении панель скрывается.

## Заказы и резервы

Добавлены поставки еды со склада в таверну. `Tavern.foodStorage` задаёт склад-источник; пустое поле допускает доступные склады. Носильщик работодателя обслуживает только собственный склад. Сначала резервируются готовая еда на складе и место в локальном запасе таверны, затем выполняются физический забор и доставка. Приоритет — таверны с наименьшим запасом. Пшеница и мука не перевозятся в качестве еды. Отмена освобождает оба резерва; уже взятая еда остаётся в рюкзаке.

- Цикл: ожидание → забрать → доставить → ожидание.
- Источники: Sawmill, StoneHouse, Fishing, FarmHouse и MiningHouse.
- При выборе заказа резервируется источник и нужное число мест в WarehouseStorage. Не выдаём заказ, если нет доступного маршрута или свободного места.
- Гранулярность резерва источника — всё здание на время одного забора. Два носильщика не направляются за одним запасом одновременно, даже если его хватило бы на два рюкзака. После забора следующий носильщик может получить новый заказ из этого здания.
- Источник сохраняет физические ресурсы до прибытия работника. После забора они переходят в GettingResources.
- Если работник закреплён за складом, он сдаёт груз только этому складу. Свободный носильщик выбирает достижимый склад со свободным местом.
- Другие пополнения склада не могут занять места, уже зарезервированные для входящих доставок. Смена вместимости ниже занятого плюс зарезервированного объёма запрещена.
- При ручном приказе, недоступном пути, выключении, гибели или смене роли носильщика заказ отменяется и резервы освобождаются. Груз из рюкзака не удаляется. После ручного приказа носильщик сначала доставляет уже взятый груз.
- При уничтожении/отключении источника или склада носильщик перепланирует задачу.
- Непоместившийся остаток остаётся в инвентаре и ждёт места, затем получает новый резерв.

Резервы источников координируют CarrierTask между собой. Прямые внешние вызовы Extract/Collect в обход системы должны учитывать заказы при дальнейшем расширении. Производственные поставки на мельницу, пекарню и в здания обучения этим изменением ещё не добавлены.

## Проверки

Исправлено возобновление поставки еды из уже заполненного рюкзака после отмены/паузы: носильщик может заново зарезервировать таверну без возврата на полный склад. Для подхода используется проекция входа на NavMesh (до 2 м); путь обновляется раз в 0,75 секунды, прибытие учитывает достижимую точку. При 15 секундах без продвижения заказ освобождается и поиск повторяется через 5 секунд с сообщением о заблокированном маршруте. Serving Point таверны используется для доставки, если отдельного BuildingEntrance нет.

Изолированные проверки настоящего WarehouseStorage: `dotnet run --project Tests/LogisticsChecks/LogisticsChecks.csproj`. Проверяются запрет переполнения резервами, изоляция владельцев, защита места от постороннего пополнения, отмена, уничтожение владельца, изменение вместимости и сохранение остатка груза. Адаптер Unity в этих проверках моделирует только окружение склада; NavMesh и игровое поведение им не проверяются.

Компиляция игровых скриптов с Unity response-файлом успешна. Play Mode ещё требуется:

1. Два носильщика, одна лесопилка с 10 дерева: только один получает этот забор.
2. Два источника и склад с 10 свободными местами: сумма резервов не больше 10.
3. Уничтожить/отключить работника по пути: другой может получить освободившийся заказ.
4. Дать ручной приказ до и после забора: резервы освобождаются, взятый груз сохраняется.
5. Удалить источник или склад в пути: нет исключений, груз не пропадает.
6. Выделить лесоруба, фермера, шахтёра и носильщика: панель обновляет задачу и груз.
