# Панель выбранного корабля

Управление товарным грузом перенесено из PortPanel в **ShipCargoPanel**. Твой Canvas создаётся вручную. Верфь строит суда; порт загружает, разгружает и ремонтирует их.

## Настройка Canvas

1. На постоянно активный объект Canvas добавь `ShipCargoPanel`. Он сам отслеживает один выделенный корабль игрока через ManagerGO. На корабль скрипт панели не добавляется.
2. Создай дочерний визуальный блок и назначь его в `Content Root`. Этот блок скрывается без выбранного корабля. Не назначай сюда объект самого ShipCargoPanel: иначе скрипт перестанет получать выделение.
3. Назначь тексты `Title Text`, `Health Text`, `Cargo Text`, `Status Text`, `Message Text`. Необязательные слайдеры: `Health Slider`, `Cargo Slider`, `Operation Slider`.
4. Создай вручную строки для дерева, камня, железа, золота и любых других товаров. На каждую добавь **ShipCargoRow**. Выбери `Resource`, свой `Resource Icon` и `Icon`, назначь `Name Text`, `Ship Amount Text`, `Port Amount Text`, `Amount Input`, `Decrease Button`, `Increase Button`. Поле `Step` задаёт шаг кнопок, по умолчанию 10. Начальное значение ввода — 0.
5. Заполни массив `Rows` либо оставь пустым: при Awake панель найдёт строки в дочерних объектах, включая выключенные. Не дублируй один ресурс в нескольких строках.
6. Назначь кнопки панели из таблицы. Скрипт подписывает их сам; вручную добавлять те же методы в OnClick не нужно.

| Поле | Подпись / действие |
|---|---|
| Load Button | «Загрузить» или «Отправить заказ»: все ненулевые количества строк из порта в трюм |
| Unload Button | «Разгрузить»: все выбранные количества из трюма в порт |
| Unload All Button | «Разгрузить всё» |
| Cancel Transfer Button | «Отменить погрузку»: отменяет оставшийся заказ |
| Repair Button | «Ремонтировать»: ремонт выбранного повреждённого корпуса в текущем порту |
| Cancel Repair Button | «Отменить ремонт» |

## Правила

- Выдели корабль и отправь ПКМ к порту. Грузовые кнопки доступны после завершения швартовки, при действующем порте игрока и дороге к входу. Просто находиться рядом недостаточно.
- «−/+» меняют количество в строке. После нажатия «Загрузить» или «Разгрузить» создаётся один заказ из всех ненулевых строк. Кнопка отправляет грузовой заказ, а не судно в плавание: направление рейса задаётся отдельно.
- Поля количества сбрасываются при смене выбранного корабля и после принятия заказа. Переключение выбора само по себе не отменяет начатую работу.
- Новый корректный заказ заменяет остаток старого. Некорректный заказ его не отменяет. Размер полного заказа погрузки должен помещаться в оставшийся объём трюма; объём общий, а не отдельный для каждого товара.
- Если товара нет в порту, носильщики доставят его со склада. Портовые рабочие выполняют реальную передачу партиями, обычно 10 единиц за 2 секунды работы. Груз не возникает при клике.
- На разгрузку нельзя заказать больше, чем есть на корабле. Полный склад порта приостанавливает разгрузку до освобождения места.
- Полоска строки показывает долю ресурса от общей вместимости трюма; общая полоска — весь груз. Провизия экипажа остаётся отдельным запасом ShipProvisions.
- Уход судна отменяет недоставленную часть. Уже перемещённое сохраняется. Автоматический рейс уступает ручному грузовому заказу.
- Ремонт имеет приоритет: его назначение отменяет текущий грузовой заказ и ставит автоматический рейс на паузу. Погрузка доступна после завершения или отмены ремонта. Заказ погрузки затем нужно задать заново.

## Панели зданий

**PortPanel** сохраняет склад, желаемые запасы, найм/увольнение и информацию о состоянии. Старые грузовые кнопки отключены; их можно удалить из своего макета. `Resource Dropdown` и `Amount Input` нужны для `Stock Target`, если используешь предварительное накопление товара.

**ShipRepairPanel** можно оставить дополнительным блоком панели порта. UiSelectBuilding привязывает его к `Port`. При ручной привязке поле `Yard` теперь ожидает компонент Port; имя поля сохранено для совместимости макета. На верфи этот блок больше не используется.

**ShipyardPanel** с EquipmentProductionPanel занимается строительством. ShipCargoPanel работает отдельно и не требует UiSelectBuilding.

## Проверка в Unity

Порт с дорогой, доступным береговым входом, BerthPoint на воде и нанятыми PortWorker → пришвартовать торговое судно → выделить его → задать два товара → загрузить → проверить рейсы носильщиков, работу порта и рост реального трюма → разгрузить. Затем проверить уход посреди партии, заполненный трюм, заполненный порт, ремонт и сохранение/загрузку.

Игровые и Editor-скрипты скомпилированы, изолированные проверки физической передачи, резервов, заказов нескольких ресурсов и ремонта проходят. Реальный Canvas и Play Mode нужно проверить после ручной привязки.
