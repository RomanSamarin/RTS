# Приоритет доставки

Носильщик выбирает новый заказ в порядке: **срочный → высокий → обычный → низкий**.
Уровень общий для разных видов работ: срочная кузница получает сырьё раньше обычной таверны.
Невыполнимые заявки пропускаются: нет ресурсов, свободной вместимости, дороги, доступного пути,
либо нужный груз уже зарезервировал другой носильщик. Низкий приоритет не означает запрет доставки.

У зданий без компонента `DeliveryPriority` приоритет обычный. Старые сцены и префабы продолжают работать.

## Настройка в Inspector

1. Добавьте `DeliveryPriority` на корень здания, где находится Tavern, RecipeBuilding или его наследник.
2. Выберите поле Priority: Low / Normal / High / Urgent.
3. Компонент также работает на лесопилке, каменоломне, ферме, доме шахтёра и прочих зданиях-источниках.

Для доставки еды используется приоритет получателя — таверны или больницы.
Для сырья — приоритет производственного здания, включая мельницу, пекарню, кузницу, мастерскую и конюшню.
Для вывоза продукции на склад — приоритет здания-источника. Для разгрузки уже находящегося в рюкзаке
свободного груза — приоритет склада-получателя; назначение носильщика своему складу сохраняется.
При одинаковом приоритете действуют прежние правила: сначала еда, затем сырьё, затем вывоз;
среди получателей еды — меньший запас, среди производств — меньший входной запас.
Ближайшие источники и склады выбираются как раньше.

## Ваша игровая панель

1. На созданную вами панель добавьте `DeliveryPriorityPanel`.
2. Назначьте TMP Dropdown в поле Priority Dropdown. Скрипт заполнит четыре пункта самостоятельно.
3. При желании назначьте TMP Text в Priority Text для подписи.

Если Target Building пустой, панель работает с текущим зданием из BuildingSelectionManager.
Для панели конкретного здания можно назначить Target Building вручную — тот же объект, на котором лежит
производство/таверна. При первом изменении в игре компонент приоритета добавляется автоматически.
Если UiSelectBuilding находится на дочернем объекте, добавьте DeliveryPriority на настоящий корень заранее
или укажите этот корень в Target Building.

Вместо Dropdown можно создать четыре кнопки и назначить методы панели:
`SetLow()`, `SetNormal()`, `SetHigh()`, `SetUrgent()`. Изменять можно только свои здания.

## Границы механики и проверка

Смена приоритета действует на **следующий заказ**: текущий груз и резервы не бросаются, не дублируются
и не переназначаются посреди пути. Порог пополнения таверны, лимиты запасов, рецепты и требования дороги сохраняются.
Строители, собственная загрузка армейских повозок и доставка снаряжения рекрутам не используют CarrierTask,
поэтому эта настройка не меняет их очереди. Механика минимального неприкосновенного запаса здесь не добавлена.

Для проверки в Play Mode используйте одного свободного носильщика и склад с едой и железом:

- У таверны запрос пополнения и Normal, у кузницы запрос сырья и Urgent: новый заказ идёт в кузницу.
- Уберите нужное сырьё: носильщик обслуживает доступную заявку таверны.
- Два носильщика: резервы не позволяют превысить заявку или забрать одни и те же материалы.
- Измените приоритет в пути: носильщик заканчивает доставку, затем учитывает новый уровень.
- Low у лесопилки: её древесина вывозится после выполнимых заявок более высокого уровня.

Постоянные срочные заявки могут надолго отложить низкие — приоритеты нужно менять по нуждам поселения.
