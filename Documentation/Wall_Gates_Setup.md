# Ворота на существующей стене

В базу зданий уже добавлены ворота **ID 68**, префаб `Assets/Learnig/Episode11_Assets_RTS/Gate.prefab`. Размеры подготовлены под текущую сетку: длина 5, высота 5, толщина 2 м. Цена перестройки — 15 дерева и 10 камня. Настраивается в Requirements записи Gate. Время берётся из Build Times для ID 68 или Default Build Time.

## Отдельная кнопка строительства

На своей кнопке Canvas → On Click назначьте существующий объект PlacementSystem и **StartGatePlacement()**. Можно использовать вариант **StartGatePlacement(int)** со значением 68 либо BuyBuilding с Database Item Id = 68. StartPlacement сам распознаёт префаб WallGate и включает нужный режим.

После нажатия кнопки выберите ЛКМ **достроенную обычную прямую секцию стены**. Башню, другие ворота, угловой соединитель и незавершённую стройку выбрать нельзя. Поворот ворот наследуется от стены. Предварительно уведите защитников с этой секции и снимите назначенные на неё позиции.

Ресурсы резервируются на складах, доставляются строителями. Исходная секция сохраняется отключённой, пока возводятся ворота. После завершения старая секция удаляется. При сносе незавершённой стройки ворота отменяются и исходная стена восстанавливается. Возврата уже доставленных материалов нет. Снос завершённых ворот оставляет свободный проём, исходная стена больше не возвращается.

## Открытие и закрытие

- Вне режима строительства нажмите **ЛКМ по воротам** для открытия/закрытия. В открытом состоянии можно нажать по стойке или верхней балке.
- Для своей UI-панели доступны методы `WallGate.Open()`, `Close()`, `Toggle()` и `SetOpen(bool)`; `Status`, `IsOpen`, `LastError` доступны для подписей.
- Створки плавно открываются за Animation Duration (по умолчанию 1.2 секунды). Проход становится доступным только после полного открытия. В закрытом состоянии BoxCollider и NavMeshObstacle блокируют проезд.
- Если в проезде стоит юнит, закрытие отклоняется. Если юнит вошёл в момент начала закрытия, ворота снова открываются. Проверка работает через NavMeshAgent, отдельный коллайдер на юните не обязателен.
- Боковые стойки продолжают блокировать проход независимо от положения створок. Верхний боевой ход остаётся доступным в обоих состояниях ворот.
- Доступно обычное открытие для всех юнитов: проверки союзов/пропуска только своих пока нет.

## Модель и анимации

Готовый Gate.prefab создаёт при запуске простую модель из стоек, балки и двух створок. Встроенная анимация плавно вращает створки, отдельный Animator для неё не нужен. В режиме редактирования этот служебный префаб может выглядеть пустым: модель создаётся в Awake.

Для своей модели назначьте Left Leaf и Right Leaf — **шарниры**, расположенные по бокам проёма. Их исходный Local Rotation считается закрытым положением. Open Angle задаёт раскрытие. Если назначены оба шарнира, примитивная модель автоматически не создаётся. Сохраните неподвижные стойки/балку, их коллайдеры и препятствия NavMesh.

Можно вместо встроенного вращения назначить Gate Animator с bool-параметром **isOpen**: false → закрывание, true → открывание. Клипы должны двигать створки, сохраняя корень ворот неподвижным; длительность открытия/закрытия должна совпадать с Animation Duration. При назначенном Animator встроенное вращение отключается, а блокировка прохода по-прежнему управляется WallGate. Если Starts Open включён, начальное состояние Animator тоже должно отображать открытые ворота.

## Проверка в Play Mode

Постройте обычную стену, затем ворота на её прямой секции. Проверьте доставку, отмену стройки с возвращением стены, открытие/закрытие, отказ закрываться на стоящем юните, маршрут через открытые ворота, блокировку закрытых ворот и движение защитника по боевому ходу сверху. После изменения carving маршрут может обновиться со следующего кадра. Изолированные тесты GateMotion не проверяют конкретную сцену, модели и NavMesh.
