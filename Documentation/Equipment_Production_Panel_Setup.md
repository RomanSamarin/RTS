# Панель кузницы и мастерской

Скрипты управляют данными и кнопками пользовательской панели. Сам Canvas, рамки, фон, шрифты, размеры, спрайты и расположение элементов создаются вручную. Во время игры скрипт размножает только назначенные вами префабы строк рецептов, стоимости и очереди.

## 1. Главная панель

Создайте объект `BlacksmithPanel` внутри Canvas и добавьте `EquipmentProductionPanel` из пространства имён `_Game.Scripts.UI`. На Canvas нужны `GraphicRaycaster`, а в сцене — `EventSystem`.

Рекомендуемая структура:

```text
Canvas
  BlacksmithPanel [EquipmentProductionPanel]
    Header: TitleText, CloseButton
    Workers: WorkersText, HireButton, FireButton
    StatusText
    RecipesRoot [VerticalLayoutGroup]
    QueueScrollView [ScrollRect]
      Viewport [RectMask2D]
        QueueRoot [VerticalLayoutGroup, ContentSizeFitter]
    Footer: QueueCountText, ClearQueueButton, RepeatToggle
    MessageText
```

Назначьте соответствующие ссылки в компоненте панели. Для текстов используйте TextMeshProUGUI. `Repeat Toggle` необязателен, остальные подписи и кнопки также можно опустить. `Message Text` показывает причины неудачного найма и увольнения.

В `Resource Icons` добавьте пары типа ресурса и спрайта: `Sword`, `Spear`, `Bow`, `Shield`, `Wood`, `Iron`. Один список используется и для товаров, и для их стоимости. При отсутствии спрайта текст остаётся, изображение скрывается.

## 2. Префаб кнопки рецепта

Можно разместить кнопки **вручную**, без префаба. Создайте дочерний объект внутри `EquipmentProductionPanel`, добавьте `ProductionRecipeRow` и назначьте `Produce Button`. В `Recipe Index` укажите номер из списка `Recipes` здания: `0` — первый рецепт (меч), `1` — второй (копьё). Для второго рецепта сделайте отдельную строку с индексом `1`. Остальные поля строки необязательны. При выборе здания панель сама привяжет такие строки к его рецептам; `Recipes Root` и `Recipe Prefab` для этого способа можно оставить пустыми. В `Button.OnClick` ничего добавлять не нужно. Индексы относятся к порядку рецептов выбранного здания, а не к номеру ресурса в ResourceType.

Если нужны автоматически создаваемые строки для всех рецептов, используйте префаб по инструкции ниже. Не размещайте дополнительные ручные строки для тех же рецептов одновременно с автоматическими, иначе будут дублирующие кнопки.

Соберите UI-строку и добавьте `ProductionRecipeRow`:

```text
RecipeRow [ProductionRecipeRow, LayoutElement]
  ProduceButton [Button]
    ProductIcon [Image]
  NameText [TMP]
  CostsRoot [HorizontalLayoutGroup]
  DurationText [TMP]
```

Назначьте `Produce Button`, `Product Icon`, `Name Text`, `Duration Text`, `Costs Root`, `Cost Prefab`. Сохраните строку как префаб и назначьте его в `Recipe Prefab` основной панели, а контейнер — в `Recipes Root`.

Стоимость автоматически читается из рецепта: у меча — 3 железа, у копья — 2 дерева и 1 железо. Нажатие добавляет одну партию в очередь. Кнопка остаётся доступной при нехватке сырья: заказ ждёт физической доставки.

## 3. Префаб стоимости

Создайте небольшую UI-строку с `ProductionCostRow`, дочерними `Image` и TMP-текстом. Назначьте их в `Icon` и `Amount Text`. Текст будет «3 железа» или «2 дерева». Префаб назначается в `Cost Prefab` строки рецепта.

Если отдельные иконки стоимости не нужны, оставьте `Cost Prefab` пустым и назначьте `Cost Text` в строке рецепта: в нём появится вся стоимость, например «2 дерева + 1 железо».

## 4. Префаб элемента очереди

Соберите строку и добавьте `ProductionQueueRow`:

```text
QueueRow [ProductionQueueRow, LayoutElement]
  ActiveHighlight [Image]
  ProductIcon [Image]
  NameText [TMP]
  StatusText [TMP]
  ProgressBackground [Image]
    ProgressFill [Image]
  ProgressText [TMP]
  CancelButton [Button]
```

Назначьте поля компонента. Для `Progress Fill` выберите в Image `Type = Filled`, `Fill Method = Horizontal`, начало слева. В поле Source Image нужен подходящий спрайт шкалы. Вместо Image можно назначить `Progress Slider`; скрипт выставит диапазон 0–1 и отключит ручное изменение.

Сохраните строку как префаб и назначьте её в `Queue Prefab` панели. `Queue Root` — Content внутри ScrollView. У Content установите `VerticalLayoutGroup` и `ContentSizeFitter` с `Vertical Fit = Preferred Size`, у строк задайте высоту через `LayoutElement`. Служебную подсветку разместите позади текста и отключите у неё `Raycast Target`.

Активен только первый заказ, остальные показывают «Ожидает» и нулевой прогресс. Активный показывает фактические проценты и секунды труда. Статус учитывает отсутствие работников, сырья, места, паузу и уход работников. Сам отсчёт времени UI не ведёт — берёт реальный `WorkProgress` здания.

Крестик отменяет именно свой заказ по постоянному номеру. Отмена ожидающего заказа сохраняет прогресс первого; отмена текущего сбрасывает его незавершённый труд, но оставляет сырьё в здании. Завершённая продукция не удаляется.

## 5. Открытие по выбранному зданию

На кузнице должны быть `Blacksmith`, `WorkplaceHiring`, `UiSelectBuilding` и Collider. В `UiSelectBuilding.Panel Name` задайте `BlacksmithPanel` или назначьте объект панели в `UI Panel` для здания, уже размещённого в сцене. Для динамически строящихся префабов используйте имя панели.

`UiSelectBuilding` автоматически вызывает `EquipmentProductionPanel.Bind` с конкретным выбранным зданием. Поэтому одна панель может обслуживать несколько кузниц, не смешивая их очереди и работников. Для мастерской создайте аналогичную панель или используйте общую: рецепты, заголовок и профессия переключатся автоматически. Для ручного открытия можно вызвать `Bind(building)`, затем включить GameObject панели.

Поле `Target` основной панели обычно оставляйте пустым: оно заполняется при выборе здания. Его можно назначить вручную для отдельного тестового окна.

## 6. Найм, кнопки и повтор

Панель сама подключает свои слушатели. **Не добавляйте те же вызовы вручную в Button.OnClick.** В `WorkplaceHiring` оставьте `Hire Button`, `Fire Button`, `Workers Text` пустыми для этой панели: ими управляет `EquipmentProductionPanel`. Иначе оба компонента могут обработать один клик.

«Нанять» использует существующий `TryHire()`, «Уволить» — `TryFire()`. Счётчик показывает работников именно выбранного здания. Закрытие окна не отменяет производство.

Для конечной очереди как на концепте выключите `Repeat Selected Recipe` на здании. При включённом повторе после конечной очереди возобновляется выбранный постоянный рецепт. Его отдельная строка отмечена «Повтор», крестик на ней отключает повтор. `Repeat Toggle` позволяет менять этот режим. Кнопка панели «Очистить очередь» отменяет все ожидающие/незавершённые заказы **и отключает повтор**, оставляя запасы и готовую продукцию.

## Проверка

Проверьте две кузницы с разными очередями, переключение между ними, найм и увольнение, окончание первого заказа перед кликом по старому крестику, отмену среднего заказа, полный выходной запас, голод работников и паузу. Проверьте мастерскую на тех же компонентах UI. Нужны ваши спрайты и настроенные префабы; концепт PNG не разбирается скриптами на готовые элементы.
