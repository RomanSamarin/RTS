# Автоматический грузовой рейс

Цикл: **порт A → загрузка → порт B → разгрузка → необязательный обратный груз → порт A → разгрузка**. При `Repeat` цикл повторяется. Корабль ничего не производит и не получает золото за расстояние: перемещаются реальные товары через существующий портовый склад и работу портовых рабочих.

## Быстрая настройка без панели

`ShipTradeRoute` автоматически добавляется на `ShipHull`, новые тестовые префабы содержат его. Запустить рейс можно только у **торгового корабля**.

1. Подготовь два здания с **Port** одной фракции с кораблём. Одного `ShipSupplyDock` на верфи недостаточно. Нужны дорога, береговой NavMesh и нанятые портовые рабочие. Носильщики обычных складов доставляют товары в порт и вывозят импорт.
2. Оба причала должны быть достижимы в общей `ShipLaunchArea`. Подготовь двух моряков и доставку съедобных припасов. Настройки: [навигация](Ship_Navigation_Setup.md), [экипаж](Ship_Crew_Setup.md), [порт](Port_Cargo_Setup.md).
3. На `ShipTradeRoute` назначь `Source Port` и другой `Destination Port`.
4. Заполни `Outbound`: например `Wood: 40`, `Iron: 20`. `Return Cargo` задаёт обратный груз, например `Stone: 30`; пустой список означает возвращение без нового груза.
5. `Repeat = true` повторяет цикл, `false` завершает один полный цикл у A. `Departure Meals = 10` задаёт минимальный запас припасов перед выходом из каждого порта, допустимо 0…вместимость провизии.
6. В Play Mode открой меню компонента **«Начать грузовой рейс»**. Аналогичные пункты позволяют поставить рейс на паузу и отменить его. Из кода: `TryStartRoute()`, `PauseRoute()`, `ResumeRoute()`, `CancelRoute()`.

Автоматического старта просто от заполнения Inspector нет. Настройки копируются при запуске; для изменения портов и грузов запусти новый рейс. Возобновление продолжает прежний план.

## Количество и физическая доставка

Количество в списке — целевой объём выбранного товара на один переход. Уже находящиеся в трюме товары засчитываются в него. Излишек не выгружается: при 80 дерева в трюме и задании на 40 в B уйдёт 40, остальные останутся на судне.

Сумма каждого направления не должна превышать вместимость трюма (сейчас 200). Повторные строки одного ресурса объединяются. Посторонний груз тоже занимает место; при его нехватке рейс ждёт освобождения трюма.

Корабль ждёт полную загрузку по списку. Порт создаёт заявки, носильщики физически приносят товары; предназначенный рейсу запас защищён от преждевременного вывоза обратно на склад. Передача порт ↔ корабль требует портовых рабочих и времени: скрипт рейса не выполняет их работу.

При заполненном порте разгрузка останавливается, остаток остаётся на судне. Носильщики могут освободить склад, после чего передача продолжается. Отсутствующая дорога приостанавливает береговые операции.

Перед отплытием проверяются полный экипаж и порог еды. При недостатке еды включается физическое пополнение. Порог применяется при выходе из порта: расход пищи в море не запрещает добраться до следующего порта для снабжения. Голод и потеря экипажа сохраняют обычные последствия.

## Занятый причал

Попытка подхода повторяется раз в 2 секунды. Готовое судно пытается освободить исходный причал, отойдя на доступную воду рядом: проверяются восемь направлений на расстоянии `max(12 м, 2 × длина корпуса)`. Это позволяет встречным рейсам освобождать порты друг для друга. Автоматическое назначение ближайшего корабля не возвращает ожидающее судно к старому причалу.

Если места ожидания нет, корабль остаётся с пояснением. Если водного пути нет, ждёт и повторяет попытку. Разъезд использует `ShipTraffic`. Полной очереди обслуживания и гарантии разъезда в любой тесной гавани пока нет. Ожидание в море расходует припасы.

## Ручное управление

- Успешный ручной приказ движения/швартовки или X/H ставит рейс на паузу; новый приказ сохраняется.
- Ручные загрузка, разгрузка и «разгрузить всё» также ставят обслуживаемый авторейс на паузу.
- Кнопка отмены в `PortPanel` использует `CancelTransferFromPlayer()`. Используй этот метод и в своём UI.
- Пауза/отмена снимают только заявки и грузовую операцию этого рейса. Другие ручные операции сохраняются. Загруженный груз остаётся на судне, доставленный — в порту.
- В море ручная пауза/отмена останавливает судно. Пришвартованный корабль остаётся у причала.
- После ручного изменения груза возобновление учитывает реальный остаток трюма.
- Уничтожение, отключение или смена владельца порта ставят рейс на паузу без удаления груза.

## Твоя панель

Добавь **ShipTradeRoutePanel** на свой Canvas. `Follow Selected Ship = true` привязывает его к одному выделенному торговому кораблю. Для ручной привязки выключи флаг и вызови `Bind(ShipTradeRoute)` или назначь `Route`.

| Поля | Элементы |
|---|---|
| Source / Destination Dropdown | Два TMP_Dropdown своих портов |
| Resource Dropdown / Amount Input | TMP_Dropdown товара и TMP_InputField количества |
| Add Outbound / Add Return Button | Добавить товар или изменить количество для направления |
| Clear Cargo Button | Очистить списки настройки, сохранив реальный груз |
| Departure Meals Input / Repeat Toggle | TMP_InputField порога еды и Toggle повторения |
| Start / Pause / Resume / Cancel Button | Начать, пауза, продолжить, отменить |
| Cargo / Status / Message Text | Списки, состояние, число циклов и ошибки |

Кнопки подписываются самим скриптом — дублировать `OnClick` не нужно. Canvas автоматически не создаётся, существующий концепт порта не изменяется.

## Сохранения и проверка

Сохраняются активные порты, копии плана, этап, остаток разгрузки, число циклов, владение грузовой операцией и её прогресс. Навигация после загрузки пересчитывает путь, грузовая операция продолжает передачу с прежними резервами.

Изолированные проверки запускают настоящий `ShipTradeRoute` вместе с `Port`, `CargoHold`, `ShipCargo`, `ShipProvisions` и `SaveStateCodec`. Проверены полный/повторный цикл, несколько ресурсов, обратный груз, нехватка товаров, заполненный порт, излишек груза, ручные приказы, питание/экипаж, ожидание причала и сохранение посреди партии. Навигация заменена адаптером прибытия.

В Unity ещё проверь реальные переходы двух судов, носильщиков и портовых рабочих, отстой, дорожные блокировки и загрузку всей сцены. Международные сделки, цены и оплата — отдельная механика.
