# Отдельная рабочая анимация isWorking

У рабочих профессий работа больше не включает боевой `isAttacking`. Единый итоговый флаг доступен как `ResourcesMove.isWorking` и передаётся в **Bool Animator `isWorking`**. Animator ищется также на дочерней модели. Регистр имени важен.

## Скрипты профессий

| Профессия | Где находится флаг `isWorking` | Когда true |
|---|---|---|
| Лесоруб, рыбак, каменщик | `ResourceWorker` | Добывает в пределах рабочей дистанции |
| Шахтёр | `Miner` | Добывает железо/золото |
| Фермер | `Farmer` | Собирает урожай |
| Охотник, сборщик ягод | `FoodGatheringWorker` | Охотится/разделывает добычу или собирает ягоды |
| Мельник, пекарь, кузнец, мастер, коптильщик | `ProductionWorker` | Выполняет рецепт с доставленным сырьём и местом для продукции |
| Корабельщик | `ProductionWorker` | Строит корпус на верфи из доставленного дерева и железа |
| Портовый рабочий | `ProductionWorker` | Перегружает товары между портовым складом и торговым кораблём |
| Строитель | `Builder` | Строит после доставки материалов или ремонтирует здание |
| Носильщик | `CarrierTask` | Забирает/сдаёт груз у здания |

В `ResourcesMove` итог берётся только у текущей профессии: оставшийся от прежней профессии компонент не управляет новой анимацией. При простое, ходьбе, отсутствии сырья/места, питании, ручном приказе, недоступной дороге и отключении работы флаг сбрасывается. У солдат, лошадей, повозок и безработных этот рабочий флаг не включается. Осадные действия солдат используют собственные параметры лестниц.

Скриптовые свойства предназначены для чтения. Итоговое значение видно в компоненте `ResourcesMove` в Inspector во время игры. Внешним кодом не нужно постоянно включать `isWorking` вручную: его определяет текущая задача.

## Настройка Animator

В каждом контроллере профессии:

1. Создайте **Bool `isWorking`** с начальным значением false.
2. Создайте отдельное состояние **Working** с нужным клипом: рубка, рыбалка, добыча, фермерство, ковка и т. п.
3. Переходы Idle/Moving → Working: `isWorking == true`, **Has Exit Time выключен**, Duration примерно 0,1–0,15 секунды.
4. Переход Working → Idle: `isWorking == false`, **Has Exit Time выключен**. Обычные переходы в движение сохраняются.
5. Для непрерывной работы включите у клипа **Loop Time**. Используйте клип In Place: положение рабочего ведёт NavMeshAgent.

На Working не нужны `UnitAttackState` и другие боевые StateMachineBehaviour. Уберите с рабочего клипа Animation Events, наносящие урон/выдающие ресурсы: прогресс уже считает скрипт, повторный вызов может дать двойную добычу.

`isAttacking` оставьте для настоящего боя. Если один контроллер используется рабочими и солдатами, добавляйте отдельное состояние Working, не переименовывайте боевой параметр во всём контроллере. При работе общий помощник сбрасывает боевую позу и ходьбу; при окончании работы он снимает только `isWorking` и не сбрасывает новый боевой приказ.

**Контроллеры и клипы автоматически не изменялись.** Без нового параметра/переходов ресурсная логика продолжает работать, но рабочий клип не запустится. Отсутствующий bool не вызывает ошибок в новом помощнике.

## Что изменилось в логике

- `ResourceWorker` автоматически добавляется лесорубу, рыбаку и каменщику через `ResourcesMove`. Подход, рабочая дистанция и тики добычи больше не требуют нахождения в состоянии атаки Animator. В `UnitAttackState` остался боевой урон; рыба и камень оттуда не добываются.
- Старое поле цели `AttackController.targetToAttack` у трёх старых профессий сохранено для совместимости с выбором источников и доставкой. Рабочий таймер и параметр анимации от боевого состояния независимы.
- Рабочая частота у этих профессий задаётся `ResourceWorker.workRate`, дистанция — `workDistance`. По умолчанию 1 тик/с и 2 м. Дерево сохраняет прежний расчёт силы удара рабочего, рыбалка и камень — по одному рабочему тику.
- Строитель больше не включает `isAttacking` и не делает принудительный CrossFade в Attack State. Его `workParameter` переводится в `isWorking`; переходы теперь настраиваются в Animator как у остальных профессий.
- Носильщик после фактической передачи груза останавливается на `handlingSeconds` (по умолчанию 0,35 с), чтобы сыграть получение/выгрузку. Сам перенос остаётся атомарным; флаг не включается на весь путь к получателю.

## Проверка

Компиляция игровых скриптов и изолированные проверки проверяют разделение рабочих/боевых bool, отсутствие параметров, приоритет прерывания и таймер добычи без Animator. Существующие проверки производства, логистики, обучения и боя также должны проходить.

В Play Mode проверьте каждый тип: подход → работа → полный рюкзак/готовая партия → доставка/простой; затем питание, новый приказ и смену профессии. Для строителя проверьте и стройку, и ремонт. У лесоруба, рыбака и каменщика временно отключите Animator и убедитесь, что ресурсы продолжают добываться один раз, а не через два источника урона. У солдата проверьте обычную атаку с `isWorking == false`.
